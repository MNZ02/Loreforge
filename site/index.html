A FEW THINGS TO KNOW

Simple by
design.

Does Loreforge run my agents?+

You start your CLI sessions. Loreforge stores the work they explicitly record. It does not launch models, schedule jobs, or create and merge worktrees.

How do different agents share context?+

Point their sessions at the same project and local state home, then add the session instructions to each client. Each agent calls the CLI explicitly. MCP clients can use the same operations as tools. Rule loading still depends on your client’s setup.

Where does the information go?+

Records live in a local SQLite database. When an agent reads a record, it may send that content to its model provider as context. A Git observation records what was seen; it does not back up uncommitted files.

Does it save tokens?+

It can give a session a useful starting point instead of another investigation. Total token savings have not been measured, and recording and retrieving context also consumes tokens.

Can I install from a local checkout?+

If you already have the Loreforge checkout, run these commands from its root. This builds and installs your local package. Use the npm command above for the published alpha.

npm install && npm run build && npm install -g .

Then run lore init in your project. Use lore doctor to check your setup. Search, correction history, reviews, MCP, and backup/restore/export are available in 0.2. Nothing is published by these commands.
